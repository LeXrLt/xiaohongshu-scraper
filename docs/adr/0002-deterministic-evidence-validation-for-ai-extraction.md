# 0002. 大模型商户抽取确定性证据校验机制

- **日期**：2026-10-12
- **状态**：Accepted

---

## 背景与痛点 (Context)

从小红书自由文本笔记中抽取结构化商户实体（店名、分类、价格、预约、区域）极度依赖大语言模型（LLM）的语义理解能力。然而，LLM 具有不可避免的缺陷：
1. **事实幻觉 (Hallucination)**：模型常基于其通用常识，自行脑补笔记中未曾提及的商户地址、营业时间、人均价格等。
2. **格式与枚举漂移**：即便有 Prompt 约束，模型仍可能输出字典外的非法分类名或泛化代称（如“这家店”、“香港餐厅”）。
3. **不可追溯**：若直接将模型输出写入正式表，后续用户或 Agent 无法获知推荐依据源自哪一句话，无法验证真伪。

---

## 决策内容 (Decision)

建立**“受控提示词 + 暂存候选表 + 确定性代码校验门禁 + 幂等晋级”**的四阶管道：

1. **强约束受控字典**：大模型仅被允许从数据库读取的 `available_categories` 与 `available_tags` 列表中挑选 ID。
2. **中间候选表隔离 (`merchant_extraction_candidates`)**：大模型解析出的结果一律先写入候选表，严禁直接落库 `merchants` 主表。
3. **确定性证据子串校验 (Deterministic Substring Verification)**：
   - 编写确定性 Python 规则：商户名 (`name`)、价格证据 (`price_evidence`)、预约证据必须能够在原始笔记正文（或标题/话题）中通过字面子串（或空白归一化子串）完全命中。
   - 无法找到原文直接证据的字段强制清空。
   - 证据匹配度低或存在歧义的候选标记为 `needs_review`，不予自动晋级。
4. **多对多关联保留原文片段**：晋级后在 `merchant_notes` 中保存完整的 `evidence_text` 及原文起止偏移量，形成完整可审计链条。

---

## 影响与后果 (Consequences)

### 正面收益
- 彻底杜绝了模型幻觉污染正式商户库的风险。
- 为后续通过 MCP 向外部 Agent 推荐商户时，提供了 100% 真实的佐证引用。
- 抽取任务失败或 Prompt 迭代时，只需针对候选表做版本化重算，不破坏现有商户关系。

### 妥协与代价
- 纯隐式或口语化代词表达的真实商户可能因证据校验严格被保守丢弃或进入待复核队列。
