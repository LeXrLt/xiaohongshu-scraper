# 0005. 细粒度任务游标与全流程幂等断点续跑

- **日期**：2026-10-13
- **状态**：Accepted

---

## 背景与痛点 (Context)

社交媒体爬虫与大模型抽取属于长生命周期、高频网络 I/O 的任务，不可避免会遇到：
- 小红书平台的动态限流与风控验证；
- 远程 API 超时、网络抖动或本地断电；
- 耗费高昂 Token 费用的大模型调用中断。

在早期实现中：
- 抓取任务每次从第 1 页开始拉取，导致前面的老数据被重复请求；
- 商户抽取每次遍历最新的一批笔记，缺乏笔记维度的抽取完成记录，空结果笔记每次都被捞出重复调用 LLM；
- 主评论与子评论游标混在一起，子评论中断后无法恢复特定树分支。

---

## 决策内容 (Decision)

建立**“单页/单实体原子提交 + 独立完成状态记录 + 游标与配额解耦”**的系统级幂等与续跑规范：

1. **配额预算与累计断点解耦**：
   - 命令行参数 `--pages` / `--max-pages` 仅定义“本次运行处理的批次上限”，而非“从第 1 页抓到第 N 页”。
   - 只要源数据未彻底耗尽，任务状态保留为当前断点游标；下次运行默认继续未完成页码。
   - 重新从第 1 页抓取必须显式指定 `--restart`。
2. **独立实体完成状态表 (`merchant_extraction_state`)**：
   - 商户抽取按笔记记录完成状态。
   - 包含三种情况：成功提取商户、未发现商户（空结果）、以及需人工复核。全部记为 `completed`，并记录当次笔记正文的 `content_hash`。
   - 增量抽取在查询待办笔记时先排除已完成笔记，彻底消除重复调用。
3. **分层分治的二级评论游标**：
   - 根评论按笔记记录翻页游标。
   - 嵌套的子评论按根评论 ID 独立保存分支游标，当分支预算耗尽时下次直接定位该分支继续，不重复重放。
4. **多模态分析持久化缓存与失败重试队列**：
   - 图片 OCR 按图片内容哈希缓存；视频按文件转录结果缓存。
   - 媒体下载和分析失败作为独立任务登记在数据库队列中，后续爬虫在主抓取列表已完成的前提下，也会优先重试这些失败任务。

---

## 影响与后果 (Consequences)

### 正面收益
- 故障恢复成本大幅降低，任意异常退出只需重新触发命令即可无损续跑。
- 极大地降低了大模型 API 的调用开销与小红书抓取请求次数，有效避免由于高频重复抓取触发风控。

### 妥协与代价
- 数据库中需维护额外的状态表（`xhs_crawl_state`, `merchant_extraction_state`），业务逻辑需要严格处理分布式事务边界。
